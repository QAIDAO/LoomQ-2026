# QUANTUM 101 · 写给没接触过量子的开发者（30 分钟版）

> **先说结论：这道题让你造的是"翻译器"，不是让你学物理。**
> 就像写 Markdown→HTML 转换器不需要会写小说，做量子指令转译不需要懂薛定谔方程。
> 这份手册覆盖本题所需的**全部**量子概念——读完它，剩下的都是你熟悉的软件工程。

---

## 一、五个概念，用程序员的话说

| 术语 | 教科书说法 | 你只需要这样理解 |
|---|---|---|
| 量子比特 (qubit) | 量子叠加态的载体 | n 个 qubit 的系统 = 一个长度 2ⁿ 的复数数组（状态向量）。qubit k 就是数组索引的第 k 个二进制位 |
| 量子门 (gate) | 幺正变换 | 对这个数组做一次矩阵运算。`h`、`x`、`cx` 只是函数名，SDK 帮你算 |
| 电路 (circuit) | 量子算法的图形表示 | **顺序执行的指令列表**——就是一段汇编。你的转译器做的事和汇编方言互转一模一样 |
| 测量 (measure) | 波函数坍缩 | 按 `abs(数组元素)²` 加权，随机采样出一个二进制串 |
| shots | 重复制备与测量 | 同一程序跑 N 次采样，返回直方图。`counts: {"00": 498, "11": 526}` 就是采样 1024 次的结果 |
| 纠缠 (entanglement) | 非局域关联 | 联合分布拆不成独立分布。Bell 态 = 两枚**永远同面**的硬币：各自 50/50，但从不出现 "01"/"10" |

就这些。本题不会用到更多。

## 二、10 分钟读懂 OpenQASM 2.0

这是你要翻译的"源语言"。逐行看 `circuits/bell.qasm`：

```text
OPENQASM 2.0;           // 版本声明，固定写法
include "qelib1.inc";   // 标准门库，类似 #include <stdlib.h>
qreg q[2];              // 声明 2 个量子比特（数组长度变为 2²=4）
creg c[2];              // 声明 2 个经典比特，存测量结果
h q[0];                 // 对 q0 施加 Hadamard 门（制造 50/50 叠加）
cx q[0], q[1];          // 受控非门：q0 为 1 时翻转 q1（制造纠缠）
measure q -> c;         // 测量全部 qubit，结果写入 c
```

你需要处理的语法**只有这么多**：版本行、include、两种寄存器声明、门调用（可带参数，如 `rz(0.5) q[1];`）、measure。没有循环、没有条件、没有自定义函数。

**门白名单**：全部评测电路（含隐藏电路与评测日变体）只使用 12 个标准门——
`h, x, s, sdg, t, tdg, rz(θ), ry(θ), cx, cu1(θ), swap, ccx`。
不会出现白名单之外的门。逐个查一遍每家 SDK 对这 12 个门的支持，就是 L1 的完整工作量清单。

## 三、counts 与位序（本题最容易踩的坑）

大赛统一约定（Qiskit 风格）：**counts 的 key 最右侧字符是 `c[0]`**。

```text
key = "10"  含义: c[1]=1, c[0]=0
```

不同平台原生返回的位序可能相反——把它们归一化成统一约定，正是你的中间层的职责之一（也是送分点：这是纯字符串处理）。

## 四、保真度：你的"测试通过率"

题面里那个 Hellinger 公式**不需要你实现**，`evaluator.py` 已经写好了。直觉版：

> 把你的 counts 归一化成概率分布，和标准答案比"相似度"，**≥ 0.97 通过**。

它实际上是二值判定：转译正确时采样涨落只会让它落在 0.99 左右；任何一个门翻错，它会跌到 0.9 以下。不存在"差一点点"的灰色地带，对了就是对了。

## 五、测试电路都是什么（人话版）

| 电路 | 人话 | 理想输出 |
|---|---|---|
| Bell / GHZ-3 / GHZ-5 | 2 / 3 / 5 枚永远同面的硬币 | 50% 全 0，50% 全 1 |
| QFT-4 | 量子版傅里叶变换，考**相位**转译精度 | 恰好 4 个 25% 的峰 |
| Grover-3 | 在 8 个抽屉里"放大"正确答案的概率 | 94.5% 概率开出 `111` |
| Random ×3 | 随机指令流，考门集覆盖完整性 | 各不相同（评测系统算好了） |

你不需要理解这些算法**为什么**有效，只需要保证每条指令被忠实翻译——译者不必赞同原文观点。

## 七、建议的前 4 小时动手路径

1. **10 分钟**：装依赖，跑 `python3 examples/run_braket.py`——看到你人生第一个量子程序的输出（本地模拟器，免费，无需注册任何账号）。
2. **30 分钟**：读 `examples/run_braket.py`，理解 QASM 2.0→3.0 与本地执行的基本流程。
3. **10 分钟**：跑 `python3 evaluator.py --level l1 --json-out report.json`，确认原始骨架会明确报告未实现。
4. **半天**：先打通一个本地模拟器，再挑第二个后端（推荐 SpinQit，原生支持 QASM 2.0）——L1 入门档到手。
5. **然后去 L2**：那才是你的主场——L2 是纯 LLM 工程（prompt 设计 + "生成 → 用自己的 L1 跑一遍自验 → 重试"闭环），量子背景在那里没有任何额外优势。

## FAQ · 新手恐慌自查

**Q: 我需要线性代数很好吗？**
不需要手算任何矩阵。你的角色是调度矩阵运算的人，不是执行者。

**Q: 隐藏电路会不会出现我没见过的门？**
不会。12 个门的白名单写进题面了，评测日变体同样受白名单约束。

**Q: 某个后端说不支持门 X 怎么办？**
翻开 `gate_identities.md`，把 X 按恒等式改写成基础门——公式可以直接照抄，全部经官方参考模拟器验证。

**Q: 真机听起来很吓人？**
真机是加分阶梯，不是资格线：两个模拟器后端跑通公开电路就有评奖资格。而且各家 SDK 里"提交真机"和"提交模拟器"通常是同一个 API 换个参数。

**Q: 题面里的数学公式看不懂？**
全题面只有一个公式（Hellinger 保真度），它已经在 `evaluator.py` 里实现好了，你永远不需要自己写。
